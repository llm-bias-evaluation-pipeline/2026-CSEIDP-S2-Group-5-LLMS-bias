# Setup & Run Guide

Paired with [`README.md`](./README.md), which explains *what* this project is.
This file explains *how to actually run it*, step by step.

🔗 **Live dashboard (for comparison once your local version is running):** https://2026-cseidp-s2-group-5.vercel.app/

```
├── aggregate.py           # evaluated data -> dashboard_data.json (incl. significance tests)
├── index.html             # the live dashboard (deployed to Vercel)
├── pipeline.py            # generates the 600-prompt matrix from events.csv
├── requirements.txt
├── config/
│   └── models.yaml        # model IDs + generation params -- cost-optimized tiers, see comments
├── data/
│   ├── events.csv         # the 60 source historical events
│   ├── prompts/           # generated by pipeline.py -- do not hand-edit
│   ├── responses/         # generated by collector.py
│   └── evaluated/         # generated by evaluate.py + combine.py
└── src/
    ├── collector.py       # calls all configured model APIs, resumable
    ├── api_clients/       # one thin wrapper per model
    │   ├── base.py
    │   ├── openai_client.py    (ChatGPT)
    │   ├── gemini_client.py    (Gemini -- defaults to free Flash-Lite tier)
    │   ├── deepseek_client.py  (DeepSeek)
    │   ├── doubao_client.py    (Doubao)
    │   ├── kimi_client.py      (Kimi K3 -- CN backup #1)
    │   └── qwen_client.py      (Qwen -- CN backup #2)
    └── evaluator/
        ├── judge.py        # LLM-judge: combined evaluate_full() call (cost-optimized, ~1 call/response)

        └── stats.py        # significance testing (Fisher's exact, CMH, chi-square)
```

## Step-by-step: from zero to a working pipeline

**Run every command from the repo root.**

### 1. Environment setup
```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 2. API keys
```bash
cp .env.example .env
```
Fill in whichever keys you have — the pipeline skips any model with no key
configured, gracefully. You don't need all of them to start.

- **Gemini** (free tier, start here): [aistudio.google.com](https://aistudio.google.com) → Get API key
- **OpenAI**: [platform.openai.com](https://platform.openai.com) → add billing → API keys. Use a cheap tier (`gpt-4.1-nano` is set as default in `config/models.yaml` — flagship is not required, confirmed by Dr Bishop)
- **DeepSeek**: [platform.deepseek.com](https://platform.deepseek.com)
- **Doubao**: Volcengine Ark platform — `DOUBAO_API_KEY` + `DOUBAO_ENDPOINT_ID`. Known to be difficult to access outside China; try Kimi/Qwen below if this fails
- **Kimi K3**: [platform.moonshot.ai](https://platform.moonshot.ai) → `KIMI_API_KEY`
- **Qwen**: [dashscope console](https://dashscope.console.aliyun.com) → `DASHSCOPE_API_KEY`

### 3. Generate the prompt matrix
```bash
python pipeline.py
```
Produces `data/prompts/prompt_matrix.csv` (600 prompts). Safe to re-run anytime.

### 4. Collect model responses
```bash
python src/collector.py --models chatgpt gemini deepseek doubao kimi qwen
```
Use any subset via `--models` if you don't have all keys yet. Resumable — if
it stops or crashes, re-running skips prompts already collected. If using
Gemini's free tier, add `--sleep 4` or higher to stay under its rate limit.

### 5. Evaluate each model's responses
```bash
python src/evaluator/evaluate.py --in data/responses/chatgpt_responses.csv --out data/evaluated/chatgpt_evaluated.csv
```
Repeat per model collected. Also resumable — safe to stop and re-run without
re-paying for already-evaluated rows.

**Test on a small slice first** if cost/quota is a concern:
```bash
head -5 data/responses/chatgpt_responses.csv > /tmp/sample.csv
python src/evaluator/evaluate.py --in /tmp/sample.csv --out /tmp/sample_evaluated.csv
```

**Judge model**: defaults to Gemini Flash-Lite (`src/evaluator/evaluate.py`,
inside `main()`) for cost reasons. See `judge.py`'s docstring for why the
judge model choice matters — a heavily-guardrailed judge can refuse to
evaluate sensitive content, which shows up as `judge_refused` in the output
rather than failing silently.

### 6. Merge evaluated files
```bash
python src/evaluator/combine.py --in-dir data/evaluated --out data/evaluated/all_evaluated.csv
```

### 7. Generate the dashboard data
```bash
python aggregate.py --in data/evaluated/all_evaluated.csv --out dashboard_data.json
```
This includes the statistical significance tests (RQ1, RQ3) alongside the
chart data.

### 8. Test the dashboard locally
```bash
python3 -m http.server
```
Open `http://localhost:8000` — confirm it shows **"● LIVE DATA"**, not the
sample-data warning banner.

### 9. Deploy
```bash
git add index.html dashboard_data.json
git commit -m "Update dashboard with real evaluation results"
git push
```
Vercel redeploys automatically within a minute or two of the push.

## Troubleshooting

- **"Nothing changed after I edited index.html"** — check the file actually
  committed (look at its commit history on GitHub) and check Vercel's
  Deployments tab for a fresh entry with a recent timestamp. If both look
  right, hard-refresh your browser (Ctrl+Shift+R) or try an incognito
  window — stale caching is the most common cause.
- **Import errors running `collector.py` or `evaluate.py`** — almost always
  a file sitting in the wrong folder. Compare your actual repo structure
  against the tree at the top of this file, path for path.
- **High `judge_refused` rate in evaluated output** — your judge model is
  itself declining to engage with sensitive content. Consider switching to
  a less-restricted model for the judge role specifically (not for the
  4 models under test).
